## 1. Редизайн выбора даты и времени записи

**Приоритет:** 🔴 High  
**Оценка:** 5–8 SP  
**Labels:** `frontend`, `ux`, `redesign`

### Описание

Текущая страница бронирования (`GuestBookingView`) отображает слоты сгруппированными по датам в виде списка.  
Необходимо заменить этот подход на двухколоночный макет:

- **Слева** — интерактивный календарь на базе `v-date-picker` из Vuetify. По умолчанию выбрана сегодняшняя дата. Пользователь кликает по дню — справа обновляются слоты.
- **Справа** — список временных слотов на выбранную дату. Свободные слоты отображаются как `v-chip` (кликабельны). Занятые слоты также отображаются, но с атрибутом `disabled` и визуально отличаются (серый цвет, зачёркнутый текст), чтобы гость видел занятость дня.

### Acceptance Criteria (AC)

- [ ] При открытии страницы бронирования календарь показывает текущий месяц, выбран сегодняшний день.
- [ ] Справа от календаря отображаются слоты на выбранную дату.
- [ ] При клике на другой день в календаре слоты справа обновляются без перезагрузки страницы.
- [ ] Занятые слоты видны, но не доступны для клика (disabled state).
- [ ] Свободные слоты кликабельны и запускают форму бронирования (как и сейчас).
- [ ] На мобильных устройствах (ширина < 600px) колонки перестраиваются в одну: календарь сверху, слоты снизу.
- [ ] Дни в календаре, на которые нет доступных слотов, визуально отличаются (например, `allowed-dates` prop или подсветка дней со слотами).

### Технические детали

**Затрагиваемые файлы:**
- `src/frontend/src/views/guest/GuestBookingView.vue` — основной рефакторинг
- `src/frontend/src/composables/useSlots.js` — добавить метод для получения слотов на конкретную дату
- `src/frontend/src/composables/useSlotUtils.js` — добавить хелпер `getSlotsForDate(slots, date)`

**Компоненты Vuetify:**
- `v-date-picker` (mode: `date`, `hide-weekdays: false`, `show-adjacent-months: false`)
- `v-row` / `v-col` для двухколоночного макета
- `v-chip` с `variant="tonal"` для свободных слотов, `variant="plain" disabled` для занятых

**Ожидаемое поведение:**
- Текущий API `GET /api/event-types/{id}/slots` возвращает слоты на 14 дней вперёд. Их нужно не перезапрашивать при смене даты, а фильтровать на клиенте.
- Если выбранная дата выходит за пределы 14-дневного окна — показывать сообщение «Нет доступных слотов».

## 2. Тёмная тема

**Приоритет:** 🟡 Medium  
**Оценка:** 3 SP  
**Labels:** `frontend`, `theme`, `ux`

### Описание

Добавить переключатель светлой/тёмной темы в интерфейс. Приложение должно поддерживать обе темы, сохранять выбор пользователя в `localStorage` и применять при следующем открытии.

### Acceptance Criteria (AC)

- [ ] В `AppHeader` добавлен переключатель темы (иконка солнца/луны, `v-btn` с `@click`).
- [ ] Переключение изменяет `theme.global.name` в Vuetify на `'dark'` / `'light'`.
- [ ] Выбранная тема сохраняется в `localStorage` (ключ `app-theme`).
- [ ] При загрузке приложения тема восстанавливается из `localStorage`; если нет — используется светлая (по умолчанию).
- [ ] Все компоненты корректно отображаются в тёмной теме (цвета текста, фоны, карточки, чипы, диалоги).
- [ ] Цветовая палитра тёмной темы определена в конфигурации Vuetify (тёмные `surface`, `background`, корректный `primary` на тёмном фоне).

### Технические детали

**Затрагиваемые файлы:**
- `src/frontend/src/main.js` — добавить тему `dark` в конфигурацию Vuetify
- `src/frontend/src/stores/app.js` — добавить состояние `theme`, методы `setTheme`/`toggleTheme`, сохранение в `localStorage`
- `src/frontend/src/components/AppHeader.vue` — добавить кнопку переключения темы
- `src/frontend/src/App.vue` — применить тему из стора при монтировании

**Конфигурация тёмной темы (main.js):**
```js

  themes: {
    dark: {
      dark: true,
      colors: {
        primary: '#90CAF9',
        secondary: '#B0BEC5',
        background: '#121212',
        surface: '#1E1E1E',
      },
    },
    light: { /* существующая */ },
  },
```

**Зависимости:** нет.

## 4. Настройка графика работы (админ)

**Приоритет:** 🔴 High  
**Оценка:** 13 SP  
**Labels:** `backend`, `frontend`, `feature`, `schedule`

### Описание

Текущая логика слотов жёстко закодирована: слоты генерируются с 09:00 до 18:00, каждый день, на 14 дней вперёд.  
Необходимо дать администратору возможность гибко настраивать рабочее расписание:

- Выбор рабочих дней недели (Пн–Вс).
- Настройка интервала работы для каждого дня (начало и конец, например 10:00–17:00).
- Возможность задать исключительный день (праздник, особый режим) с кастомным временем работы.
- Отметка нерабочих дней.
- Слоты формируются только в рамках рабочего расписания.

### Подзадачи

#### 4.1. Модель данных и миграции

**Файлы:** `database/migrations/`, `app/Models/`

- [ ] Создать миграцию для таблицы `work_schedules`:
  - `id` — primary key
  - `day_of_week` — integer (0 = Sunday, 6 = Saturday)
  - `is_working_day` — boolean (по умолчанию true для Пн–Пт)
  - `start_time` — time (например 09:00)
  - `end_time` — time (например 18:00)
  - `created_at`, `updated_at`

- [ ] Создать миграцию для таблицы `schedule_overrides` (исключения):
  - `id` — primary key
  - `date` — date (конкретная дата)
  - `is_working_day` — boolean (false для выходного, true для рабочего)
  - `start_time` — time (nullable, если `is_working_day = false`)
  - `end_time` — time (nullable)
  - `reason` — string (nullable, описание причины)
  - `created_at`, `updated_at`

- [ ] Создать Eloquent-модели: `WorkSchedule`, `ScheduleOverride`

#### 4.2. Backend API

**Файлы:** `routes/api.php`, `app/Http/Controllers/`, `app/Http/Requests/`, `app/Services/`, `app/Repositories/`

- [ ] `CRUD /api/admin/work-schedules` — управление рабочим расписанием (GET/PUT)
- [ ] `CRUD /api/admin/schedule-overrides` — управление исключениями (GET/POST/PATCH/DELETE)
- [ ] Рефакторинг `GET /api/event-types/{id}/slots` — генерация слотов с учётом:
  - Рабочего расписания (`work_schedules`)
  - Исключений (`schedule_overrides`) — приоритет над базовым расписанием
  - Существующих бронирований (занятость)
- [ ] Сервис `SlotGenerationService` — централизованная логика генерации слотов:
  - Принимает `dateFrom`, `dateTo`, `duration`
  - Итерирует по датам, для каждой определяет рабочий статус и интервал
  - Генерирует слоты с шагом `duration` в рамках интервала
  - Исключает занятые слоты

#### 4.3. Frontend — страница настройки (админ)

**Файлы:** `src/frontend/src/views/admin/AdminScheduleView.vue`, composables

- [ ] Новая страница `/admin/schedule`, доступная из `AdminDashboardView`
- [ ] Таблица рабочих дней недели: чекбокс «Рабочий день» + поля `start_time` / `end_time` для каждого дня
- [ ] Кнопка «Сохранить» — PUT на `/api/admin/work-schedules`
- [ ] Секция «Исключительные дни»:
  - Список существующих исключений с датой, статусом, интервалом, причиной
  - Кнопка «Добавить исключение» → форма: выбор даты, рабочий/нерабочий, время (если рабочий), причина
  - Возможность удалить исключение
- [ ] Календарь на странице бронирования (`GuestBookingView`) должен подсвечивать нерабочие дни (серый цвет, недоступны для выбора)
- [ ] При попытке создать бронирование на нерабочий день — ошибка с понятным сообщением

#### 4.4. Acceptance Criteria

- [ ] Админ может задать произвольные рабочие дни недели и интервалы.
- [ ] Админ может добавить исключительный день (праздник) с особым графиком или без работы.
- [ ] Нерабочие дни в календаре гостя недоступны для выбора.
- [ ] Слоты формируются строго в рамках рабочего расписания.
- [ ] Исключения переопределяют базовое расписание (например, рабочий вторник может быть объявлен нерабочим).
- [ ] При отсутствии настроек используется дефолтное расписание (Пн–Пт, 09:00–18:00).
- [ ] Покрыто тестами (`SlotGenerationService` + feature-тесты контроллеров).

## 5. Чат между гостем и админом

**Приоритет:** 🟡 Medium  
**Оценка:** 13 SP  
**Labels:** `backend`, `frontend`, `feature`, `chat`

### Описание

Добавить минимальный чат, где гость может отправить сообщение администратору, а администратор — просмотреть и ответить.  
Без регистрации: гость указывает имя и email, админ видит все диалоги в едином списке.

### Подзадачи

#### 5.1. Модель данных и миграции

**Файлы:** `database/migrations/`, `app/Models/`

- [ ] Создать миграцию для таблицы `chat_conversations`:
  - `id` — primary key
  - `guest_name` — string
  - `guest_email` — string
  - `subject` — string (nullable, тема обращения)
  - `last_message_at` — timestamp
  - `created_at`, `updated_at`

- [ ] Создать миграцию для таблицы `chat_messages`:
  - `id` — primary key
  - `conversation_id` — integer
  - `sender_type` — enum (`guest`, `admin`)
  - `message` — text
  - `is_read` — boolean (default: false)
  - `created_at` — timestamp

- [ ] Eloquent-модели: `ChatConversation` (hasMany `ChatMessage`), `ChatMessage` (belongsTo `ChatConversation`)

#### 5.2. Backend API

**Файлы:** `routes/api.php`, `app/Http/Controllers/`, `app/Http/Requests/`, `app/Services/`

Guest API:
- [ ] `POST /api/chat/conversations` — создать обращение (гость)  
  Body: `{ guest_name, guest_email, subject?, message }`  
  Возвращает: `conversation` + первое сообщение
- [ ] `POST /api/chat/conversations/{id}/messages` — отправить сообщение в существующий диалог (гость)  
  Body: `{ sender_type: "guest", message }`
- [ ] `GET /api/chat/conversations/lookup?email=...` — найти диалог по email гостя

Admin API:
- [ ] `GET /api/admin/chat/conversations` — список всех диалогов (с последним сообщением и счётчиком непрочитанных)
- [ ] `GET /api/admin/chat/conversations/{id}/messages` — все сообщения диалога
- [ ] `POST /api/admin/chat/conversations/{id}/messages` — ответ админа  
  Body: `{ sender_type: "admin", message }`
- [ ] `PATCH /api/admin/chat/conversations/{id}/messages/read` — отметить сообщения как прочитанные

#### 5.3. Frontend — гость

**Файлы:**
- `src/frontend/src/views/guest/GuestChatView.vue`
- `src/frontend/src/composables/useChat.js`

- [ ] Кнопка «Чат с админом» в `AppHeader` для роли `guest`.
- [ ] Страница чата:
  - Если гость ещё не начинал диалог — форма: имя, email, тема (опционально), сообщение.
  - После отправки — интерфейс чата: список сообщений (свои справа, админа слева) + поле ввода.
- [ ] Гость может найти свой предыдущий диалог по email (через `GET /lookup`).
- [ ] Сообщения загружаются при открытии и обновляются по таймеру (polling каждые 10 сек) или вручную.

#### 5.4. Frontend — админ

**Файлы:**
- `src/frontend/src/views/admin/AdminChatView.vue`
- `src/frontend/src/views/admin/AdminChatConversationView.vue`

- [ ] Пункт «Messages» в `AdminDashboardView` + бейдж с количеством непрочитанных.
- [ ] Список диалогов (`AdminChatView`): имя гостя, тема, последнее сообщение, дата, индикатор непрочитанных.
- [ ] При клике на диалог — страница переписки (`AdminChatConversationView`):
  - Сообщения гостя слева, админа справа.
  - Поле ввода для ответа.
  - Отметка прочитанных при открытии диалога.

#### 5.5. Acceptance Criteria

- [ ] Гость может начать новый диалог, указав имя и email.
- [ ] Гость может найти свой предыдущий диалог по email.
- [ ] Админ видит список всех диалогов с сортировкой по дате последнего сообщения.
- [ ] Админ видит количество непрочитанных сообщений в каждом диалоге.
- [ ] Админ может ответить на сообщение гостя.
- [ ] При открытии диалога админом непрочитанные сообщения помечаются как прочитанные.
- [ ] Покрыто feature-тестами (гость создаёт диалог, админ отвечает).
- [ ] Сообщения экранируются от XSS на бэкенде.
